Notes de design — Proposal A

Hierarchie d'information
Le header CO sticky donne au joueur un acces permanent a son solde et son revenu estime. Le bouton "Generer le revenu" est place dans le header car c'est une action hebdomadaire importante — pas dans un menu secondaire.

Pattern accordeon
Les tuiles utilisent un accordeon plutot qu'une navigation push. A 4-6 tuiles par joueur, tout tient sur un ecran. Le joueur voit d'un coup d'oeil ses terrains, revenus et colonies sans changer de vue. L'expansion revele les details et les actions (construire, upgrade).

Badges compacts
Chaque tuile collapsed montre 3 infos cles : type de terrain (icone + label), revenu (badge CO dore), et statut de colonie (pill coloree). Pas besoin d'ouvrir pour comprendre l'etat.

Construction dialog
Bottom sheet modale standard mobile. Les batiments militaires (Caserne, Ecuries, etc.) montrent les variantes base/amelioree en chips inline — le cout se met a jour. Les batiments de faction apparaissent automatiquement selon la faction du joueur.

Historique CO
Vue secondaire accessible depuis le header. Chaque transaction montre un type iconique (revenu vert, construction rouge, manuel gris), un label, un montant signe, et une date. L'historique permet au joueur de verifier ses depenses et l'origine de ses revenus.

Etat vide
CTA centre avec explication. Le joueur comprend immediatement ce qu'il doit faire. La configuration initiale des territoires est un flow separe (non mockupe ici).

Choix Proposal A
— Header CO sticky (toujours visible) plutot qu'un card separee
— Accordeon mono-niveau (pas de sous-accordeons pour batiments)
— Slots de batiments en liste lineaire avec bouton "+" pour construire
— Toggle switch pour l'adjacence fluviale (pas un champ numerique)
— Bottom sheet pour la construction (pas une page entiere)
— Historique en vue separee (pas un panel lateral)
